# 《等你回来》× 音色「蛋卷」音质诊断与流程调优

诊断对象：源 `20260921_011033_ef4e.wav`（48k 立体声 221.1s）→ 音色 `蛋卷.pth`
最新一次换声：`runtime/output/20260929_001532_b8ed3541.json`
（`pitch=-6 / rmvpe / index_rate=0.6 / protect=0.15 / rms=1.0 / filter_radius=3`）

用户反馈的三个听感问题：**① 偶尔出现奇怪的声音 ② 电音 ③ 高音没有声音**。

## 一、归属判断（结论先行）

| 环节 | 是否主因 | 依据 |
|---|---|---|
| **音色制作（训练）** | **不是主因**，但有两个可改点 | 644 切片、F0/HuBERT 全部成功；loss 收敛（mel 30.17→28.48）；训练素材连续音域中位 314.7Hz、p95 476.5Hz、max 742Hz —— **高音覆盖充分**，不存在"没学过的高音" |

## 三、根因 1（最严重）：变调建议整体失效

`app.py:_rvc_f0_stats` 读的是 `logs/<stem>/2a_f0/*.npy`。

- `2a_f0` 存的是 **量化成 1–255 的整数 mel bin**（`train/dataset/extract_f0.py:coarse_f0`），**不是 Hz**；
- 真正的连续 Hz 音高在 `2b-f0nsf`。

后果：蛋卷被算成 `median_hz = 89`（其实是 bin 序号），于是对源唱 365.8Hz 给出
`raw_semis = -24.47 → suggested_pitch = -24`，并在每次换声的 note 里反复提示"下次试 -24"。
真实舒适音域中位是 **314.7Hz**，正确建议是 **-3 半音**（-6 已经偏低约 3 个半音）。

用户实际用了 -6 / 0，没采纳那个 -24，属于侥幸躲过；但界面和产物 meta 一直在给出错误引导。

## 五、推荐配置（**已固化到页面，不用手填**）

推荐值不是写在文档里让人抄——新增 `GET /api/rvc/models/{name}/recommend` 作为**唯一真源**，
页面三个入口共用同一份数字：

1. **换声页默认值**：打开页面 / 切换音色即自动拉取并**自动套用**（用户手动改过旋钮后就不再覆盖）
2. **推荐参数卡片**：换声页参数区顶部「🎯 这个音色的推荐参数」，逐项列出值 + 理由，
   并实时提示「✓ 当前已是推荐值」或「· 已偏离，点一键套用恢复」
3. **历史页「送去换声」**：提交前先确保推荐值已加载，变调 prompt 默认给上次算出的推荐值

后端没收到这些参数时，服务端默认值也是同一套（`_rvc_convert_params`），
所以**即使前端一个字不改，提交走的也是推荐值**。

### 实测推荐值（蛋卷 + 《等你回来》源中位 365.8 / p95 480.1 / p5 270.3）

```
pitch = -3          ← 源唱中位 366Hz → 音色实测中位 315Hz，差 -2.6 半音
f0_method     rmvpe
index_rate    0.5
protect       0.33
rms_mix_rate  0.25
filter_radius 3
resample_sr   0（模型原生）
```

变调是唯一需要知道源唱音高才能定的参数：没点「分析音域」时接口老实返回 `null`，不猜。
| f0 算法 | 先 **rmvpe**，高音仍丢就换 **fcpe** | 本机 `torchfcpe` 已装、CLI 已支持；rmvpe 在高音区判成无声的概率更高 |
| index_rate | **0.5**（电音明显降到 0.3） | 训练集经过 UVR 二次处理，音质不如分离干声，检索别拉满 |
| protect | **0.33** | 官方默认，兼顾咬字与音色 |
| rms_mix_rate | **0.25** | 官方现行默认，跟原唱动态走，静音段不再被填气声 |
| filter_radius | **3**；体检报八度跳变就 **5~7** | 毛刺时才加，调大会发闷 |
| 人声分离 / 去和声 / 静音门 | 全开 | 本机链路已验证 |

**训练参数（下次重练蛋卷时）**

| 参数 | 值 |
|---|---|
| 净化档位 | medium（素材底噪 -23.6dBFS，light 压不住） |
| 轮数 | 先 **60**（现模型 100 轮已收敛，但电音重时可试降轮数找回底模细节） |
| 切片峰值归一 | 已自动（新代码） |
| 素材 | 补 10 分钟以上**低底噪、峰值留 3dB 余量**的干声，重跑体检确认底噪 < -35dBFS |

# 追加：第二轮（`20260929_022340_678cc5d4`，同一首《等你回来》，pitch=+2）

用户反馈：**比之前好太多，但很多地方依然失真**；并认为"推荐的参数是 +2，太高了"。

## 1. 先纠正一个事实：推荐值不是 +2，是 -3

该单 meta 里写得清清楚楚：

```
params.pitch                 = 2
pitch_advice.suggested_pitch = -3      ← 系统推荐的是降 3
pitch_advice.pitch_used      = 2
pitch_note: "…差 -2.6 半音；本单用了 +2（换声后人声中位被拉到约 411Hz）。
             结果若发紧/电音重，下次试 -3"
```

+2 是**实际提交的值**，只可能来自手动填写 / 快捷按钮 / 历史页带入。
**缺陷不在算法，在于：推荐值摆在那儿，用户填飞了，系统一句话没说。**

## 2. 失真根因：+2 把 29% 的音高推出了蛋卷练过的范围

同口径（dio、voiced-only）重新对齐后：

| | 中位 | p5 | p95 | p99 |
|---|---|---|---|---|
| 源唱《等你回来》 | 365.8 | 270.3 | 480.1 | 585.1 |
| 蛋卷训练素材 | 311.2 | 195.9 | 485.1 | 540.4 |
| **产物（pitch=+2）** | **415.1** | 305.5 | **589.7** | 659.6 |

- 产物中位比蛋卷训练中位**高 4.99 个半音**
- **29% 的音高高于训练 p95、6.3% 高于 p99** → 模型在这些高度上基本没学过，只能硬凑
  → 就是那一片一片的失真
- 越界最重的时间段：**175s（44%）·190s（39%）·80s（36%）·150s（34%）·65s（20%）**
- 电平侧完全干净：人声 peak 0.548 / full_song peak 0.887，**零削波、零平顶**——
  不是响度问题，是音高越界问题

**安全变调区间 = -5 ~ -1**（源 p95 480Hz 抬 2 个半音 = 539Hz > 训练 p95 476Hz，
所以这组合根本不该升调）；推荐值 -3 正落在区间正中，+2 越了 3 个半音。

## 3. 顺带排除的两个怀疑

1. **训练音域统计偏高？** 拿 `1_16k_wavs` 用 dio 逐片重测（voiced-only）得中位 311.2Hz，
   对比 `2b-f0nsf` 口径的 314.7Hz —— **只差 0.07 半音**。统计没问题。
2. **`2b-f0nsf` 里 22% 是 unvoiced 插值帧？** 剔除后中位 311.4，差 0.01 半音；
   仅 p95 差 0.6 半音。对中位数无实质影响，**不值得为此换口径**。

## 4. 这轮的修复

| 改动 | 作用 |
|---|---|
| `_rvc_pitch_safe_range`（新） | 算**安全变调区间**：源 p95→音色 p95（上界）、源 p5→音色 p5（下界）；两端打架时如实标 `feasible=false`，不编假区间 |
| 推荐值收进区间 | `_rvc_recommend_params` 里 clamp，保证推荐值一定在区间内 |
| `/recommend`、`/pitch/advice` 返回 `safe_range` | 文案直接写「安全区间 -5 ~ -1」 |
| 质检新增 `out_of_range_ratio` / `far_out_ratio` | **补上质检最大盲区**：上一版对这次产物只报"丢声与音高跳变都在正常范围"，完全没抓到"音高越界"这种失真 |
| 前端越界拦截 | 推荐卡片显示安全区间；pitch 越界时变调框下方红字警告；点「开始换声」弹确认框讲清后果再让用户决定 |

新质检对这次产物的实测：

```
out_of_range_ratio = 0.2907    far_out_ratio = 0.0627
tips: 有 29% 的音高超过该音色练过的上限（p95 476Hz）——这就是那一片一片的失真…
      把变调往低调 3 个半音再试，或换一个音域更高的音色
```

## 5. 结论

上一轮的参数调优是有效的（index_rate 0.5 / rms 0.25 / 段间交叉淡化），所以"好太多了"。
剩下的失真不是参数没调好，而是**变调 +2 把人声整体抬出了音色的音域**——
按推荐值 **-3** 重跑即可；现在页面会在填飞之前拦住。

## 七、第三轮：页面自相矛盾（"推荐 +2"却又说"+2 超出安全区间 +17~0"）

用户点「分析音域 → 变调建议」，页面给出：

```
应用 +2（当前 0）
源唱中位 124Hz … 建议变调 +2 半音（音域差 +16.1）
已按该音色高音覆盖（p99 549Hz）收过上限
安全区间 +17 ~ +0        ← min>max，区间反转
⚠️ 变调 +2 超出这个音色的安全区间 +17 ~ 0（超了 2 个半音）。推荐 +2。   ← 自己打自己脸
```

### 两个独立 BUG 叠加

**BUG A（根因）—— 源唱音域根本没测准，却被当成真值用**

124Hz 是**整曲带伴奏**的测量结果：dio 被贝斯/底鼓拽到低音区。
分离后的真值是 **365.8Hz**。端点自己的 caveat 里就写着"整曲带伴奏时 f0 会被伴奏污染"，
但**仍然拿它算出了 +16 半音 → 被 p99 钳成 +2 → 前端自动套用**。
用户没有手填 +2，是系统套的。

**BUG B —— 反转的安全区间被照单全收**

源音域比音色覆盖还宽时，`min > max`（17 > 0），此时该区间**无解**。
但后端照样返回、前端照样显示、照样拿它做越界判断 →
任何值都"越界"，连推荐值 +2 自己都被判越界。

### 修复

| 位置 | 改动 |
|---|---|
| `_rvc_pitch_suggestion` | 新增 `suspicious`：**音域差 ≥13 半音**（超过一个八度）即判定源音域测错——正常换声最多跨 ±12（男女声互换），再往上基本都是伴奏污染 |
| `/rvc/pitch/advice` | 可疑时 `suggestion=None` + 返回 `suspect.hint`，**一个数字都不给**；可疑时不再输出假区间文案 |
| `/rvc/pitch/advice` | 新增 `separate` 参数：勾上先跑人声分离再量（整曲必勾，慢 1~2 分钟但准） |
| `_rvc_recommend_params` | 同样防住：可疑时 `pitch=None`，不会被自动套用 |
| 前端 `rvcPitchOutOfRange` | `!safe_range.feasible` 时直接返回 0，不做判断 |
| 前端区间显示 | 不 feasible 时显示"源唱音域与该音色练过的范围不重叠，给不出区间"，不再显示 `+17 ~ +0` |
| 前端分析流程 | 可疑时红字提示 + **自动帮用户勾上「先做人声分离」** + 不写 `rvcSrcF0`、不套用任何值 |

### 修复后实测

```
场景1（整曲污染 124Hz）: pitch = None, suspect = True   ← 不再给 +2
场景2（分离后 365.8Hz）: pitch = -3, safe_range = [-5, -1], feasible = true
```

- 段间交叉淡化已消除阶跃，但每段的音量归一化仍在段内独立发生（`audio_max` 是全局算的，已无此问题）。
