# RVC 最佳实践对标：如何让用户便捷地练出好模型、做出高质量换声

调研来源：RVC-Project 官方仓库 README、官方 Wiki FAQ（常见问题解答）、官方 CLI 源码、
Applio（社区最活跃的分支）、以及社区调参共识。
对标对象：本工程 `runtime/rvc`（vendored RVC）的「音色制作」与「歌曲换声」两条流水线。
调研时间：2026-09-27

## 一、官方口径（有出处，先立标准）

### 数据集（FAQ Q10 / README）
- **推荐 10–50 分钟**；"保证音质高、底噪低"前提下，音色有特色时多多益善。
- 高水平素材（精简 + 音色有特色）**5–10 分钟也够**，仓库作者自己经常这么玩。
- 1–2 分钟能成功但不可复现，**1 分钟以下不建议**。
- README 原话：推荐至少收集 **10 分钟低底噪语音数据**。

### 轮数（FAQ Q9）
- **训练集音质差、底噪大 → 20~30 轮就够**，调太高"底模音质无法带高你的低音质训练集"。
- 音质高、底噪低、时长多 → **200 轮是 OK 的**。
- 即：**轮数由素材质量决定，不是越多越好。**

### index_rate 的本质（FAQ Q11，这段最值得抄进产品文案）
- 底模和推理源的音质如果高于训练集，它们会带高结果音质，代价是音色往底模/推理源靠，这叫**音色泄露**。
- index_rate 就是用来削减音色泄露的：**调到 1 理论上没有推理源泄露，但音质更倾向训练集**；
  训练集音质比推理源低时，调高 index_rate **反而可能降音质**。
- **如果训练集优质且时长多，应该调高 total_epoch，此时 index_rate 不重要，甚至可以不建索引。**

### 其它官方要点
- Q18：**不要中途变更采样率继续训练**，要换就换实验名从头训。
- Q8：训练显存不够就缩 batch size；4G 以下基本没救。
- Q14：`提取音高/处理数据的 CPU 进程数`要酌情调低，素材别太长（内存会炸）。
- Q4：分享用 `weights/` 下 60MB 级的 pth + index；`logs/` 下几百 MB 的是实验状态，不能直接推理。
- README：官方主打 **RMVPE**（InterSpeech2023）"根绝哑音问题，速度快、资源占用小"。
- README：可用 ckpt-merge 做**模型融合**改变音色。

### 官方 CLI 现状（与本工程 vendor 的完全一致，已逐行比对）
```
--f0-method  choices = ["pm", "rmvpe"]      ← 没有 fcpe / crepe / harvest
--index-rate 默认 0.75   --protect 默认 0.33   --rms-mix-rate 默认 1.0
--resample-sr 默认 0     ← 默认不重采样
没有 --filter-radius
```
`filter_radius` 是官方 **WebUI** 上存在的旋钮（中值滤波半径，默认 3），
社区口径是"平滑音高毛刺、削弱哑音，哑音明显时调到 5~7"，但**当前上游 CLI 没暴露它**——
也就是说我们走 CLI 这条路，这个旋钮是缺的（这不是我们改坏了，是上游 CLI 本身没给）。

## 二、社区 / Applio 方向的补充共识

| 项 | 共识 |
|---|---|
| **f0 算法** | rmvpe 是当前通用首选；**fcpe（torchfcpe）** 是新一代"又快又准"，Applio 等分支已支持；crepe 最准但慢且吃显存；pm 最快最糙。歌声场景优先 rmvpe / fcpe。 |
| **采样率** | 40k 是社区标准（v2 默认）；48k 多一点点高频、代价是算力和素材要求。 |
| **素材预处理** | 分离伴奏 → **降噪 → 去混响**是标准三步；过度降噪比轻微底噪更糟（会产生伪影）。 |
| **切片** | 先按静音切，单段 5–10 秒为宜；训练侧 slicer 再切成固定长度训练单元。 |
| **选点** | "最好的检查点往往不是最后一个"，甜区多在 150–400 轮之间，必须能逐个试听。 |
| **音色像不像** | 源与目标**音域差太远**时效果必崩；这是"换了但不好听"最常见的原因。 |
| **电音 / 金属音** | 主因：过训、素材有混响或噪声、音域不匹配、index_rate 过高、音高提取不准。杠杆依次是：补干净素材 > 降 index_rate/降 protect > 换 f0 算法 > 调 filter_radius。 |
| **后处理** | 成品侧做 de-ess（6–8kHz）、轻微混响、压缩、EQ 匹配，社区普遍认为能再上一个台阶。 |

## 四、建议做什么（按落地顺序）

### A1（P0）素材净化：把"降噪 + 去混响"加成训练流水线的可选步骤
现在：`separate_vocal` 用 PyMSS 去掉伴奏 → 直接 40k 切片。
建议：在分离之后、切片之前，加一个**可选的净化步骤**（默认对非干声开启）：

```
上传素材 → PyMSS 去伴奏 → [新增] 去混响 → [新增] 轻降噪 → 体检 → 切片 → F0 → 特征 → 训练
```

实现要点：
- 体检报告里已有"静音段/爆音/响度"，可以顺带给出一个**混响与底噪的粗略判定**，据此默认勾选。
- **降噪务必保守**：社区明确警告"过度降噪比轻微底噪更糟"。建议给出一个强度档位（轻/中），默认轻。
- 净化前后的素材都留档，让用户能 A/B 对比——净化这一步一旦过头就不可逆。
- 体检报告增加一行"已净化：去混响/降噪（强度：轻）"，并在建议轮数里体现（净化后素材质量上升，可推荐更高轮数，对齐 FAQ Q9）。

### C4（P0）音域匹配 + 自动变调建议（本工程最该做的差异化能力）
**目标**：让"换出来不好听"从玄学变成可诊断、可自动修正。

实现要点（依赖本机已具备，不需要新装任何东西）：
- **目标音色的音域**：训练时已经把每个切片的 f0 落在 `logs/<name>/2a_f0/*.wav.npy` 里了。
  训练收尾时顺手算一次全集中位音高与 p5–p95，写进任务（`f0_median_hz` / `f0_p5` / `f0_p95`），
  并在音色卡片上显示"这个音色的舒适音域 ≈ X–Y Hz"。
- **源人声的音域**：`pyworld` 本机可用（`import pyworld` 通过），用 dio/harvest 抽源人声 f0 取中位数即可，
  几秒钟，不需要 GPU。
- **建议变调**：`pitch = round(12 * log2(目标中位 / 源中位))`，夹在 ±24 内，
  在换声页显示成一句人话：`源唱的调比这个音色低 5 个半音，建议 +5（当前 0）`，一键应用。
- **体检侧同样受益**：素材音域覆盖率（p5–p95 跨多少个半音、高音段占比）应该进体检报告，
  直接回答"为什么我这个音色一唱高音就电"。

这一条同时解决 A3，也是我认为**投入产出比最高**的一项：
官方没做，社区只能靠经验试，而我们已经有 f0 数据和 pyworld。

### C1（P1）补 fcpe
- 装 `torchfcpe`，在 vendored `infer/cli.py` 的 `--f0-method` choices 里加 `fcpe`
  （需在 `infer/vc/modules.py` 的 f0 分支里接上）。
- 页面上给三档说明：**rmvpe（通用首选）/ fcpe（新、快、准）/ pm（最快，质量最低）**。
- 注意：训练侧仍用 rmvpe（改训练侧的 f0 算法需要重新抽特征，成本大、收益不明确）。

### C2（P1）把 filter_radius 加回 CLI
- 上游 CLI 没暴露，需要我们在 vendor 的 `infer/cli.py` → `infer/vc/modules.py` → `pipeline.py`
  这条链上加一个 `--filter-radius`（默认 3）。
- 页面文案：默认 3；**哑音、毛刺、断续明显时调到 5~7**；调太大会发闷。
- 这条对"高音电音、声音发毛"这一族投诉最直接。

### C3（P2）`--resample-sr` 默认改回 0（原生采样率）
- 现状：`app.py` 硬编码 `48000`。本机三个音色里 **王菲 / 邓丽君 是 40k 模型**（孙燕姿是 48k），
  也就是这两条的每一次换声都在做一次 40k→48k 的额外重采样。
- 40k 模型的 Nyquist 是 20kHz，上采样到 48k 不会凭空补出高频；而混音环节
  `_mix_vocal_accompaniment` 本来就会按伴奏采样率对齐，不需要提前统一。
- 建议：默认 0（跟随模型原生），高级选项里可填 44100/48000。
  同时把代码里那句"40k 直出会损失高频"的注释改掉——前提是错的。

### A2 / A4（P2–P3）体检从"只报"升级到"能治"
- A2：训练前把素材统一归一化到 **-3 dB peak**（或 -20 LUFS），一步到位，社区标准做法。
- A4：体检报告里给"一键剔除"——把底噪超标、爆音占比超阈值、有效人声太短的切片直接移出数据集，
  并显示"剔除 N 条，剩余 X 分钟"。用户不用回文件夹自己找。

### B1（P2）48k 训练（可选，看是否值得）
- 需要额外下载 `f0G48k.pth` / `f0D48k.pth` 与对应的 mute 样本，且训练/推理成本都更高。
- 建议先做 A1/C4，48k 作为后续可选项；如果要做，务必遵守官方 Q18：**换采样率必须换实验名从头训**，
  不能在同一个任务上 resume。

### D2（P2）短样本 A/B 试参数
- 换声前先只跑**前 30 秒**，用 2–3 组候选参数（如 index_rate 0.6/0.75/0.9，protect 0.15/0.33）
  各出一份短样本并排放在一个播放器里，用户选完再跑全长。
- 成本可接受（一次推理十几秒 × 3），但把"十几分钟后才知道参数不对"变成"半分钟内知道"。

## 六、一句话结论

我们工程在**工程化**（串行队列、索引归属、提交前闸门、检查点可回退、静音门、不丢立体声、
体检、自动自检）上已经明显强于官方 WebUI，这部分不用再动。

真正决定"用户能不能练出好模型、换出高质量"的，剩下三件事：
1. **素材净化**（去混响 + 轻降噪）——决定音质上限，官方和社区都把这一步排在第一；
2. **音域匹配与自动变调**——把"换了不好听"从玄学变成可诊断、可自动修正，且我们已有 f0 数据和 pyworld，几乎是白捡的能力；
3. **补 fcpe 与 filter_radius**——把歌声换声的两个关键旋钮还给使用者。

按 A1 → C4 → C1/C2 → C3/A2/A4 的顺序做，前两项做完，用户体感的提升会最明显。

### 7.3 新发现的问题

#### H1（P1）`filter_radius` 取偶数时，整条换声崩掉

`scipy.signal.medfilt` 要求核为奇数。校验只查了 `0 ≤ fr ≤ 7` 的整数，**4 和 6 能过闸门**，
然后在子进程里抛异常。端到端实测（`--filter-radius 4`，同一条音频）：

```
File "runtime/rvc/infer/vc/pipeline.py", line 130, in get_f0
    f0 = signal.medfilt(f0, filter_radius)
ValueError: Each element of kernel_size should be odd.
```

而 `--filter-radius 3` 同一条音频成功。也就是说：用户在页面上把"音高平滑半径"填 4 或 6
（number input，step=1，随手可填），换声会**在排完队之后**直接失败。

修法（两处任选，建议都加——一处钳位、一处兜底）：

```python
# app.py :: _rvc_convert_params，校验段末尾
# 中值滤波核必须是奇数：scipy.signal.medfilt 对偶数核直接抛 ValueError。
```

#### H2（P1）vendored RVC 的改动不进版本库，旧 runtime 上所有换声会全崩

C1/C2 的改动落在 `runtime/rvc/infer/cli.py` 与 `pipeline.py`，而 `.gitignore` 第 2 行是 `runtime/`
（`git check-ignore -v` 已确认）。后果有两层：

1. **改不动就丢**：别人 clone 仓库、或本机重装 runtime，拿不到这两处改动；
2. **更糟的是现在会硬崩**：`app.py` 无条件在命令里加 `--filter-radius`，而旧 CLI 不认识这个参数，
   argparse 直接 `unrecognized arguments` 退出（exit 2）——**换声 100% 失败**，且是每次提交都失败。

建议三件事一起做：
- 把这两处改动以补丁形式入库（如 `patches/rvc-cli-fcpe-filter.patch` + `scripts/apply_rvc_patch.py`），
  或在 `.gitignore` 里对 `runtime/rvc/infer/` 这几个文件开白名单；
- `app.py` 加**能力探测**，不支持就降级而不是崩：

```python
_RVC_CLI_CAPS: dict | None = None

def _rvc_cli_caps() -> dict:
    """探测 vendored CLI 实际支持哪些旋钮（runtime/ 不进版本库，可能被重装/换机器）。"""
    global _RVC_CLI_CAPS
    if _RVC_CLI_CAPS is None:
        txt = ""
        try:
            r = subprocess.run([str(RVC_PY), str(RVC_DIR / "infer" / "cli.py"), "--help"],
                               capture_output=True, timeout=60,
                               env={**os.environ, "PYTHONPATH": str(RVC_DIR)})
            txt = (r.stdout or b"").decode("utf-8", "ignore")
        except Exception:
            txt = ""
        _RVC_CLI_CAPS = {"filter_radius": "--filter-radius" in txt, "fcpe": "fcpe" in txt}
    return _RVC_CLI_CAPS
```

否则不传并在任务里记一条 warn（"本机 RVC 版本不支持音高平滑，已跳过"）——不许静默更不许崩。

### 10.3 过程中自己挖出来、当场填掉的坑（评审可参考复核）

1. **包名别名崩**（这是 A1 唯一的真机拦路虎）：VR 架构模型内部要 import `pymss.modules.*`，
   而 vendored 的 `modules/_core_shims.py:8-10` 硬性要求本地包前缀必须是 `pymss.modules.`。
   沿用换声链路的 `-m tools.pymss.cli` 会抛 `invalid local module alias`——
   分离链路从不碰 `.modules`，所以这个坑一直没暴露。A1 全部走 `-m pymss.cli`，
   用例 `test_two_stages...` 直接锁死 `cmd[:4]`，防将来有人"顺手统一"改回去。
2. **声部名不能做子串匹配**：实名取自权重配套 yaml——去混响输出 `Dry/Reverb` 或
   `noreverb/reverb`，降噪输出 `Noise/No Noise`。"No Noise" 含 "Noise"、
   "noreverb" 含 "reverb"，谁用子串谁挑反。改成归一化后的**完整名**精确名单
   （`_RVC_CLEAN_KEEP_NAMES/_RVC_CLEAN_DROP_NAMES`，app.py:4255）。
3. **中档曾经"永远够不着"**：底噪最初只统计 -45 dBFS 静音门以下的帧——
   越噪的文件"静音帧"越少，噪声大到中档标准时反而一个静音帧都没有，判定永远 off。
   改成每文件取帧能量第 10 百分位（不依赖静音门），用例锁死 -38.8 dBFS → 荐「中」。
4. **全败不许留下"假净化"**：`_rvc_clean_dataset` 先算出真实净化数，若为 0 则在
   往 `dataset_purified/` 挪任何文件**之前**就 raise——否则续跑会把"原样拷进来的
   未净化文件"误判成已净化直接跳过。
5. **前缀抢名**：切片 `s.wav` 会 glob 到 `s0_Dry.wav`（`s_*.wav` 匹配它），
   `_rvc_clean_select` 过滤掉后缀里还带 `_` 的候选，用例专门造了 s/s0 撞名场景。
