# v2.0 规划：音乐工作台页面重构（10+1 页）

> 面向开发人员的实施规划。基线版本 **v1.7.1**（2026-10-03），仓库 `RevolutionLA/YuE2-Music-Workbench`，默认分支 `master`。  
> 本文所有"现状"结论均来自对 `static/index.html`（5814 行）、`app.py`（7386 行）、`src/*.py`、`tests/` 的实读，行号可直接定位。

---

## 一、为什么要重构

v1.x 的主界面是 6 个页签：**创作 / AI 工作台 / 歌曲换声 / 音色制作 / 音色库 / 任务管理**。问题集中在「创作」页：它一个面板塞进了四件事——

| 挤在「创作」页里的事                                             | 位置                                                  |
| ------------------------------------------------------ | --------------------------------------------------- |
| Style 文本组装（12 大类 / 106 条曲风配方 / 4 张词表 / 六要素装配台 / 预算与自检） | `index.html:851-921`，JS `1802-2600`                 |
| 歌词编辑 + 结构校验 + 撤销栈 + 曲式骨架                               | `index.html:803-826`，JS `2705-2854`                 |
| 歌曲生成（含 6 个采样参数、模型档位、连发次数、进度 ETA）                       | `index.html:830-833` + 折叠区 `940-999`，JS `3376-3701` |
| 从参考歌曲提取乐谱（SheetSage2）+ ABC 编辑器 + 乐谱库                   | `index.html:961-973`，JS `3703-3868`                 |

第二个问题是**设置无家可归**：健康灯、模型校验/修复、CUDA/CPU 切换、主题、主题色挤在侧栏 `.side-foot`（`743-770`），模型量化档切换又埋在创作页的折叠区里（`944`），而端口、输出目录、日志这类真正常用的设置项**前端一处都没有**。

第三个问题是**有几件事根本进不来**：人声/伴奏分离在后端已完整可用（`_run_vocal_separation` `app.py:3957`），但只作为换声流程的内部步骤，用户想"只分离一下"没有入口；转谱产出的 MIDI/lab 文件躺在 `sheetsage2-output/` 里，前端一个都拿不到。

**重构目标**：把一条链路上的每个环节拆成独立页面，让"我在做哪一步"这件事在界面上是自明的；设置独立成页；把后端已经具备但被埋起来的能力暴露出来。

## 二、不可动摇的现状约束（先读这段再动手）

这些是硬事实，规划里所有设计都建立在它们之上，踩了会返工。

### 2.1 进程与端口（真源 `ports.json`）

| 服务       | 端口       | 形态                           | 说明                                                                        |
| -------- | -------- | ---------------------------- | ------------------------------------------------------------------------- |
| gateway  | **7863** | `py312\python.exe -s app.py` | FastAPI，**纯 API**（`gateway_serve_ui=False`），改完 `app.py` **必须重启 7863 才生效** |
| dsh      | **3081** | node                         | **UI 唯一入口**，`/lab/*` 本地托管 `static/`，`/lab/api/*` 反代 7863                  |
| audiocpp | **8080** | `cpp/audiocpp_server.exe`    | YuE2 GGUF 推理引擎                                                            |

- `static/index.html` 由 3081 **每次请求读盘**（HTML 带 `no-store`），改前端**刷新页面即可**，不用重启。
- 前端源码里写的是 `/api/...`，运行时由 `LAB_BASE`（`index.html:1353-1381`）猴补丁成 `/lab/api/...`。**新页面继续写 `/api/...`，不要手写 `/lab` 前缀**，否则直连 7863 时会 404。

### 2.2 引擎能力边界

- **YuE2 不支持 ICL 参考音频**。引擎的 yue2 请求参数只有 `style/lyrics/cot/abc/cfg_scale/seed/num_inference_steps` 与两组采样参数，**没有任何 audio/reference/prompt 字段**（`main.pyd` 与 audiocpp 二进制已确认）。  
  → 任何"用参考音频控制音色"的页面设想在引擎层无解。可行路径只有两条：**参考音频 → 转谱 → 按谱生成**，或 **生成后 RVC 换声**。这两条正是本次第 ③④ 页与第 ⑪ 页。
- stage1/stage2 对前端不可见，进度只能整体估算。不要设计"分阶段进度条"。
- 生成前会检查 `_commit_free_mb() < 8000` 直接拦下（`app.py:1583`），CUDA 模式下显存不足自动切 CPU（`1598-1607`）。

### 2.3 页签契约（改造的支点）

```js
// index.html:1787-1800
$$(".tab").forEach(t => t.onclick = () => switchTab(t.dataset.tab));
function switchTab(name) {
  $$(".tab").forEach(x => x.classList.toggle("active", x.dataset.tab === name));
  $$(".panel-tab").forEach(p => p.style.display = p.id === "tab-" + name ? "" : "none");
  history.replaceState(null, "", "#" + name);
  parent.postMessage({type:"yue2-lab-tab", tab:name});   // 通知 dsh 侧栏
  if (name === "history") renderHistory();               // 进入时刷新
  ...
}
```

**加一个页面 = 加一个 `<button class="tab" data-tab="X">` + 一个 `<section class="panel-tab" id="tab-X" style="display:none">`**，再按需在 `switchTab` 里挂一行刷新回调。这个契约极简且可靠，本次重构**沿用，不换路由框架**。

### 2.4 其他必须知道的坑

- 三套并行轮询实现（`pollJob` 2s / `pollRvc` 5s / `pollRvcTrain` 10s，各带 Map 句柄与 miss 计数），新页面不要再抄第四份——见 §7.1。
- 两套历史源并存：`runtime/output/*.json`（`/api/generate/list`）与 `runtime/data/records/history.json`（`/api/history`），前端两个都读。任务管理页必须明确口径。
- 转谱有串行锁 `_SCORE_ENGINE_LOCK`（`app.py:639`），**并发两次会互相覆盖** `sheetsage2-output/`。新页面必须锁住 UI，不能让用户连点两次。
- RVC 换声队列在**网关内存**（`_RVC_QUEUE`），网关重启后排队条目会丢（README 已诚实声明）。新页面不要承诺"重启后排队继续"。
- FunASR/torch 推理非线程安全，`src/lrc_align.py` 用 `_infer_lock` 串行化，**不要移除**。
- 改仓库内 `.bat` 必须 UTF-8 + CRLF；用文本模式写会把 `\n` 翻译成 `\r\n` 造成 `\r\r\n`。

### ③ 参考歌曲提取乐谱（`score`）

**定位**：上传音频 → SheetSage2 转谱 → ABC 乐谱可编辑、可分析、可入库、可送 ④。

**直接复用**：

- 转谱提交 JS `3755-3783`：`#abcAudio` → `POST /api/score`（multipart `audio` + `melody_only`）→ 轮询 `/api/score/result`（前端 3s × 最长 20min）。
- ABC 编辑器 `#abc`（textarea.mono，现 `961`）+ 分析 `analyzeAbcDebounced`（`3730`）→ `POST /api/abc/analyze` → `renderAbcAnalysis`（`3706`，输出调性/拍号/BPM/音域/曲式/建议档位）。
- 乐谱库 `loadScoreList`（`3825`）：`GET /api/scores` / `GET /api/scores/{id}` / `DELETE /api/scores/{id}`。
- 「提取时带和弦」勾选 `#abcChords`（`969`）→ `melody_only=False`。


**需要新增**：
1. **独立页面化**：现状这些控件埋在创作页折叠区里（`961-973`），搬到本页主位，上传区做成大拖拽框。
2. **转谱锁 UI**：后端有串行锁 `_SCORE_ENGINE_LOCK`（`app.py:639`），并发会互相覆盖。**提交后必须禁用上传与提交按钮**，直到本任务结束，并给出"转谱中，请勿再提交"的明确提示。

## 五、跨页面数据流（共享 store）

现状已有两条持久化：`yue2_compose_form`（`5741-5782`，表单值）与 `yue2_compose_asm`（`2117/2248`，装配台选择）。拆成 11 页后，页间要传 4 样东西：**Style 文本 + asm 配方 / 歌词 / ABC 乐谱 / 生成参数**。

**方案**：新建统一 store，替换现有两条。

```js
const LabStore = {
  key: "yue2_lab_store_v2",
  state: { style:"", asm:null, lyrics:"", abc:"", scoreId:null, params:{} },
  set(patch){ Object.assign(this.state, patch); this.save(); this.emit(); },
  save(){ localStorage.setItem(this.key, JSON.stringify(this.state)); },  // 防抖 400ms
  on(fn){ ... }, emit(){ ... }        // 同页/跨页订阅
};
```

- 各页面在 `switchTab` 触发时读取 store 刷新自己的输入框；写入时回写 store。
- **手改过的值优先级最高**：任何页面手改 Style 后，set `dirty:true`，其他页面的自动回填不得覆盖（现有 `markStyleDirty` `2123` 语义升级）。
- 「→②」「→④」这类跳转按钮 = `LabStore.set(...)` + `switchTab(...)`。
- 迁移：首次启动时从旧的 `yue2_compose_form` / `yue2_compose_asm` 读一次并转存，避免用户已填内容丢失。

**必须打通的 6 条流转**（每条都要有手工用例）：
1. ① → ②：Style 文本 + 配方
2. ① → ④：Style 文本 + 配方
3. ③ → ④：ABC 乐谱 + scoreId
4. ⑦ → ⑪：分离后的人声作为音源
5. ⑦ → ⑤：分离后的去和声人声作为训练素材
6. ⑦ → ③：分离后的伴奏作为转谱输入
7. ⑧ → ①/②：AI 产出回填 Style / 歌词

## 七、前端工程建议

### 7.1 先抽公共件，再拆页面

现状有三份几乎相同的轮询实现（`pollJob`/`pollRvc`/`pollRvcTrain`，各带 Map 句柄、miss 计数、404 降级）。**先抽成统一 `startPoller(kind, rid, {interval, onTick, onDone})`，再拆页面**——否则第 ⑦ 页会诞生第四份拷贝。同样要抽的：`inlineForm`（已有，`1428`）、任务卡渲染（`.hist-item`）、结果卡（播放/下载/LRC/送去换声）。

### 7.2 文件组织

`static/index.html` 已经 5814 行，拆 11 页后会逼近 9000 行。

- **P0 阶段**：保持单文件，按页分区，每页 JS 包进 `const PageXxx = (() => { ... })()`，用 `/* ===== 页：Style 组装 ===== */` 分隔。理由：单文件托管最稳（3081 每次读盘），先保证功能不丢。
- **P1 之后**（可选）：拆成 `static/app/store.js` + `static/app/page-*.js` + `static/app/common.js`，`index.html` 用 `<script src="/lab/app/xxx.js">` 引入。3081 本地托管 `static/`，多文件同样可读盘；注意相对路径要写成 `/lab/app/...` 或在 `LAB_BASE` 里统一处理。

### 7.3 样式

**不要重写 CSS**。现有令牌（`index.html:12-89`，双主题 + `--grain` 颗粒 + 四档拟物阴影）与组件库（`.grid/.pane/.sec/.chip/.pcard/.fold/.six/.budget/.flow/.step/.hist-item/.progress/.dock`）覆盖度足够 11 个页面。新增样式只允许追加在文件末尾的 `/* v2.0 新增 */` 区块。

## 十、明确不做（本版范围外）

避免范围蔓延，以下不在 v2.0：

1. **五线谱可视化渲染**（abcjs 等）——本期乐谱只做文本态 + 分析摘要。
2. **AI 工作台原生化**——保持 iframe，v2.1 候选。
3. **ICL 参考音频生成**——引擎层不支持（§2.2），无解，不做。
4. **MusicXML / PDF 谱面导出**——只做 `mid` 与 `abc`。
5. **端口 / 输出目录 / 并发策略的在线修改**——设置页只读展示。改了会与启动脚本、看门狗不一致，风险大于收益。
6. **stage1/stage2 分阶段进度**——引擎对前端不暴露分阶段状态。
7. **换声队列持久化**——网关内存队列，重启即丢，保持现状并在 UI 上诚实说明。
8. **换前端框架 / 引入构建工具**——维持原生单页 + 本地托管。
