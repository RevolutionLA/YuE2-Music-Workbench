## 二、新发现的问题

### 2.1 J1（P1）C4 在本机 0% 覆盖：4 个可用音色全是下载音色

```
weights/: 孙燕姿.pth  王菲.pth  王菲V6.pth  邓丽君.pth
有 2a_f0:     无          无         无          无        ← 全部没有训练素材
（有 2a_f0 的是 兔/兔2/兔裹煎蛋卷/e2etest，都不在音色库里）
```

后果：`_rvc_f0_stats()` 对当前**每一个**可用音色都返回 `None` → `pitch_advice` 永不生成，
worker 里那句很实用的 `pitch_note`（"音域差 +7.0 半音，本单只变了 0，下次试 +7"）**永远不会出现**。
换声页的「分析音域」每次都会说"这个音色没有音域数据，无法给变调建议"。

> 这条也是我上一轮判断不完整的地方：我当时说 C4"几乎是白捡的能力"，
> 只看到了"训练侧有 f0 数据"，没算**用户的音色有多大比例是自己练的**。
> 本机这个比例是 0/4。

#### ⚠️ 先堵一个错误思路：不能用"换声产物"反推目标音域

最自然的补救想法是"换声跑完后，量一下产物音高，当作该音色的舒适音域"。**这在原理上是错的**，
实测证据（同一首源歌、pitch 都是 0、两个不同音色）：

| 产物 | 中位音高 | p5 / p95 |
|:---|:---|:---|
| 孙燕姿换声结果 | **316.9 Hz** | 270.9 / 493.9 |
| 邓丽君换声结果 | **315.2 Hz** | 269.6 / 484.5 |

两者只差 **0.09 半音**。RVC 是 voice conversion——**保留源 f0 曲线**，只换音色。
产物音高 ≈ `源音高 × 2^(pitch/12)`，里面**不含任何目标音色音域信息**。
谁要是照这个思路做，会得到"所有音色舒适音域都一样"的假档案。

#### 正确补救：给音色补一段"本人参考音频"建档

目标音域的物理含义是"这个人的嗓子唱到哪一段最自然"，唯一可信来源就是**这个人的声音**。
训练素材是一种，参考音频是另一种——而下载音色（孙燕姿/王菲/邓丽君）的参考音频用户随手就有。

```python
# 新增：POST /api/rvc/voices/{name}/f0-reference（复用 _rvc_f0_of_audio，几秒出结果）
#   上传一段该音色本人的歌（10~30 秒足够）→ 算中位/p5-p95
#   → 写入 sidecar runtime/rvc/logs/<stem>/f0_stats.json（_stamp 换成参考音频的 mtime）
#   → _rvc_f0_stats 的取值顺序：sidecar → 训练 2a_f0 → None
```

- 成本：后端就是现有两个函数拼一下；sidecar 结构已有，只需让 `_rvc_f0_stats` 接受"外部建档"这一路来源。
- 必须保留的诚实口径：建档来源要**区分标注**（`source: "reference" | "training"`），
  音色卡片显示"舒适音域 ≈ …（来源：参考音频 12 秒）"，不许把参考音频的数字说成训练素材实测。
- 顺带解决"改名搬 sidecar"的同一族问题：参考音频建的档跟着音色走。

做完这一步，C4 才对下载音色生效。

### 2.3 J3（P3）`_rvc_pymss_stage` 存在"零产出却报成功"的窗口

我实测撞到过：给 `-i` 传一个**实际不存在**的目录，PyMSS 子进程 `returncode=0`、零产出，
而 `_rvc_pymss_stage` 按约定返回 `""`（成功）。

真实流程里 `-o`/`-i` 都是绝对路径且目录已存在，**不会触发**；`_rvc_clean_dataset` 又是按产物文件
判成败的，兜得住。但只要将来 PyMSS 升级或换机器后行为变化（比如模型加载失败仍退 0），
这个窗口就会变成"净化静默跳过、拿未净化素材继续练"。

建议在 `_rvc_pymss_stage` 里加一道：

```python
    err = _one(in_dir)
    if not err and not any(out_dir.iterdir()):
        return "PyMSS 退出码 0 但没有任何产物（输入未命中或模型未生效）"
    return err
```

一行的事，把静默失败提前暴露。

### 2.4 J4（P3）音域体检要上传整首

`/rvc/pitch/advice` 接受 200MB 上限的整曲上传，而 `_rvc_f0_of_audio` 只读前 300 秒、
且带伴奏时数字会被污染（代码里已有 caveat）。前端若直接丢整首，是几百 MB 换一个参考值。
建议：前端允许只传片段，或用「换声完成后 meta 里的 `src_f0`」作为可信值回填（worker 侧已经量了
分离后的人声，那条才是准的）。

### 5.2 一处刻意的偏离：训练素材永远优先，参考音频不许盖它

评审建议的取值顺序写字面的 `sidecar → 训练 2a_f0 → None`。我们按 **训练 → 建档 → None** 实现，
并且**本机有 `2a_f0` 时建档接口直接 409**：

- 理由：`2a_f0` 是这个音色切片级的第一手 f0 证据；参考音频往往带混响、经过母带，精度更低。
  让低精度来源覆盖高精度来源，等于给用户一条"把自己的音色档案改坏"的路径。
- 空目录例外：`2a_f0/` 存在但**没有 npy**（训练走到预处理前就中断的机器就是这么留的，本机
  `j2cleanprobe` 即此状态：目录在、0 个 npy）时回落到建档档——这时"训练优先"会退化成"永远没数据"。
- 来源必须区分标注：sidecar 里存 `source: "reference" | "training"`，音色卡片显示
  "来源：参考音频 N 秒 / 训练素材实测"，`pitch_advice` 文案同样带上。用例锁的是"参考音频建的档
  绝不被说成训练实测"这句文案，不只锁字段。
- 旧 sidecar（训练收尾写的、无 `source` 字段）读出时补 `training`，不会因为缺字段被当成参考音频。

### 5.3 端点选择与闸门（与评审给的草案不同处）

- 路径用 `/rvc/models/{name}/f0-reference`，不是 `/rvc/voices/...`：本机音色列表接口一直叫
  `_rvc_models()`，页面与删除/改名路由都在 `models` 这一族下，另起 `voices` 会留第二套命名。
- 上传上限 **60MB**（评审草案未定），比 `/rvc/pitch/advice` 的 200MB 严——建档只需 10~30 秒，
  给 200MB 只会诱导丢整首进来（与 J4 同一口径）。
- 探测不过就 422 且**不写 sidecar**：纯静音素材建的档是假的音域。清理走 `finally` 的临时目录，
  失败也不留残渣。
- 改名自动带走建档：`f0_stats.json` 早在 v1.2.0 就在改名的搬移清单里，建档无需另做。

### 5.6 K1：删一条换声记录，盘上留三个孤儿（自查发现，非评审点名）

J2 清理时发现 `DELETE /api/generate/<id>` 返回 `{"ok":true}`，而
`<id>_accompaniment.wav` / `<id>_full_song.wav` / `<id>_vocals_original.wav` 三个文件仍在。
根因：`_output_purge` 的白名单是 `rid + 后缀`（`.wav/.json/.txt/.lrc/.lrcjob/.elrc`），
多产物叫 `<id>_名字.wav`，结构上命不中——而 `_rvc_job_purge` 的注释早就写着"孤儿是真实问题类
（1.8GB/21 个任务就是这么攒出来的）"。

修法不给 glob（rid 来自 URL），改成**读该任务 meta 登记的 `assets` 名单按名删**，且只接受
`<id>_*.wav` 这个形状。HTTP 真实路径复验：本任务 4 个文件一次删净，而 meta 里故意塞进 `assets` 的
`../app.py` 与别人任务的 `20260921_163548_a292_full_song.wav` 都还在。
边界如实记录：meta 损坏或已被单独删除时多产物仍会留盘——宁留不误删。
