# 歌词时间轴：从「转写后匹配」改为「强制对齐」

> 结论先行：歌词文本是已知的，这是一个 **forced alignment（强制对齐）** 问题，不是 ASR 识别问题。
> 旧实现走的是识别路线，本机实测起唱点误差中位数 **2.07s / 2.93s**；改为强制对齐后降到 **0.66s / 1.38s**，
> 且不再出现「歌词时间轴跑到歌曲结束之后」这类硬伤（旧实现实测有 5 行超出音频时长，最大误差 33.4s）。
>
> 最终形态：中文 → `fa-zh` 字级强制对齐；英文 → `wav2vec2` CTC 词级强制对齐；两者都用 VAD 起音点吸附校正。
> **SenseVoice / faster-whisper 已从这条链路上彻底移除。**

---

## 一、旧实现为什么必然跑偏

`src/lrc.py` 的链路是：whisper/SenseVoice 把歌声**转写**成文本 → 用模糊匹配把歌词行贴到识别段上 → 缺失的行插值补。

四个结构性问题：

| # | 问题 | 后果 |
|---|---|---|
| 1 | 路线选错：让 ASR 去"猜"歌词，再拿猜测结果反推时间轴 | 歌声上漏识率 20-30%，一旦识别错，时间轴跟着错 |
| 2 | 匹配打分用**字符集合交集**（`sum(ch in seg for ch in set(line))`），完全丢弃字序 | 中文常用字高度重合，任意两句歌词都能得 0.3+ 分，阈值 0.22 形同虚设 |
| 3 | 未命中行按 2.5s/行 顺延 + 单调钳制 1.0s | 误差沿行序累积，越到结尾越偏，尾部发散 |
| 4 | 对齐对象是**含伴奏的混音** | 伴奏能量污染 ASR/VAD，起唱点定位抖动 |

另外查出两个**实打实的 bug**（已修复）：

- **VAD 段从未生效**：`_transcribe_segments_sv()` 里用 `isinstance(c, (list, tuple))` 过滤 VAD 输出，
  但 fsmn-vad 在整段 numpy 输入下返回的是 `[{'key':.., 'value':[[beg,-1],[-1,end],...]}]`——dict 永远不匹配，
  `ivs` 恒为空 → 整轨兜底成 1 段 → `len(segs) < 3` → 永远回落 whisper。
  也就是说注释里写的「SenseVoice+VAD 主路径」**从上线起就一次都没跑过**。
- **单位错误**：即便解析修好，`a / 16000.0` 把毫秒当成 16kHz 采样点，时间点会被压缩 16 倍。

修复后可以看到 VAD 正常工作，但也能直观看到 SenseVoice 在歌声上的错识有多离谱：

```
摆了一本又一本厚砖  →  百你一半又一半
读书考学            →  好奇
估尽千境万况        →  孤樽千几
```

这正是"识别路线"不可救药的现场证据——也是最终把 ASR 从该链路彻底剔除的依据。

## 二、业界方案横评

| 方案 | 路线 | 中文歌声 | 英文歌声 | 本地可跑 | 结论 |
|---|---|---|---|---|---|
| **FunASR `fa-zh`** | 强制对齐（Paraformer-timestamp） | **好** | 不支持（无英文词表） | ✅ funasr 1.2.0 已装，模型 151MB | **中文采用**。输入 (音频, 文本) → 每字毫秒级时间戳 |
| **torchaudio CTC + wav2vec2-base-960h** | CTC 强制对齐 | 词表只有英文 | **好** | ✅ torchaudio 2.7 已装，模型 360MB | **英文采用**。把歌词拼成字母序列，CTC 强制对齐，逐词输出 |
| WhisperX | whisper + wav2vec2 对齐 | 中文对齐模型弱 | 好 | 需额外模型 | 英文生态成熟但依赖 whisper，重合度高、无必要 |
| stable-ts `align()` | whisper 时间戳精修 | 中 | 中 | ✅ | 作者已归档（2026-05），不再演进 |
| lyric-align | 字符级模糊锚点 | 中 | 中 | 需 torch | 本质仍是"ASR 后匹配"，旧思路的改良版 |
| syncalong | whisper + Needleman-Wunsch | 中 | 中 | 需 rapidfuzz | 同上，仍依赖识别质量 |
| MFA / aeneas | 发音词典 / DTW | 中文需词典 | 需词典 | 重 | 不适配本场景 |

**核心判断**：只要歌词已知，就该走强制对齐——它不做识别，因此根本不受漏识影响，字级误差在百毫秒量级。
中英分属两个词表体系，所以是**双主路径**而不是"一条主路径 + 一条兜底"。

## 三、本机实测（自生成歌曲）

基准：fsmn-vad 检测出的人声起音点（onset）作为参考真值；口径对齐业界（中位数误差、≤0.5s/≤1s 命中率）。

### 样本 A · 《来见》179.3s

| 方案 | 误差中位 | 误差均值 | 最大 | ≤0.5s | ≤1s | 落在人声内 | 超出音频 |
|---|---|---|---|---|---|---|---|
| 旧实现 | 2.07s | 2.02s | 4.48s | 15% | 27% | 100% | 0 行 |
| 强制对齐 | **0.66s** | 1.25s | 5.35s | **38%** | **62%** | 100% | 0 行 |
| +VAD 吸附 | 0.00s | 0.94s | 5.35s | 62% | 62% | 100% | 0 行 |

### 样本 B · 《来见》161.4s

| 方案 | 误差中位 | 误差均值 | 最大 | ≤0.5s | ≤1s | 落在人声内 | 超出音频 |
|---|---|---|---|---|---|---|---|
| 旧实现 | 2.93s | **7.03s** | **33.36s** | 0% | 23% | 73% | **5 行** |
| 强制对齐 | **1.38s** | **1.59s** | 3.83s | 12% | **38%** | **96%** | 0 行 |
| +VAD 吸附 | 1.38s | 1.36s | 3.83s | 38% | 38% | 96% | 0 行 |

> 关于"+VAD 吸附"一行的说明：吸附把行首对齐到 VAD 起音点，而评分基准也是 VAD 起音点，
> 因此该行指标含自证成分，**请以前两行的独立对比为准**。吸附的价值在于消除 fa-zh 的系统性漂移
> （实测 fa-zh 行首比 VAD 起音点晚 +0.5~0.7s，85%/73% 为正偏），真实精度需人工听辨最终确认。

### 英文 CTC 实测（样本 C · 英文 City Lights 版，56.2s）

`method=ctc-wav2vec2`，8/8 行命中，VAD 段 11、吸附 6，首行 11.79s。逐词 eLRC 输出：

```
[Verse]
[00:11.79]<00:12.32>NEON <00:13.76>FADES <00:14.90>ALONG <00:16.00>THE <00:16.66>LANE
[00:18.05]<00:18.16>FOOTSTEPS <00:19.60>KEEP <00:20.40>THE <00:21.04>TIME <00:22.34>OF <00:22.54>RAIN
[00:23.78]<00:24.02>FOLD <00:24.78>THE <00:25.50>NIGHT <00:26.54>AND <00:26.84>LEAVE <00:27.82>IT <00:28.02>HERE
```

词间间隔与实际演唱节奏一致（`THE` 这类虚词拿到 ~0.5s 窄窗），单调性良好。

## 四、新方案设计（`src/lrc_align.py`）

```
歌词文本 ──┐
           ├─► [1] 语种判定（CJK 占比 ≥0.3）─┬─ 中文 ─► fa-zh 强制对齐 ─► 字级时间戳
音频文件 ──┘                                └─ 英文 ─► wav2vec2 CTC 强制对齐 ─► 词级时间戳
                                                          │
                                          [2] VAD 起音点锚点吸附（消除系统性漂移）
                                                          │
                                          [3] 缺失行加权插值 + 单调钳制
                                                          │
                                          [4] 输出 .lrc（行级）+ .elrc（逐字/逐词卡拉OK）
```

- **中文主路径 fa-zh**：整轨一次性对齐（179s 音频实测约 1 秒完成，CPU）。
- **英文主路径 CTC**：`wav2vec2-base-960h` 词表外字符会直接判失败（不猜），`|` 作词分隔符，
  用 `torchaudio.functional.forced_align` + `merge_tokens` 得到 span；词数漂移时按比例适配并记录日志。
- **VAD 吸附**：窗口 ±1.2s，每个 VAD 段只服务一行，且强制保持单调——对齐模型负责"哪行属于哪段"，
  VAD 负责"这段从哪一刻起唱"。
- **末级回退 `vad-distribute`**：两条对齐路径都不可用时，用 VAD 段锚定 + 按行内音节/词数加权分布。
  这是确定性铺排，**不假装精确**（诊断里 method 会如实标注），比旧的 ASR 兜底更诚实。
- **诊断输出**：`method` / `match_rate` / `vad_segments` / `vad_snapped` / 首尾行时间，写入 `.lrcjob`
  并经 `/api/generate/lrc/{rid}` 回传，前端可据此提示可信度。

### 关键工程约束：模型推理必须串行

FunASR `AutoModel` 与 torch 模型实例**都不是线程安全的**。`app.py` 的 `_lrc_build_async()` 是
`threading.Thread` 一任务一线程，多首并发对齐时会同时进入同一个模型实例，结果随机抛异常：

```
Sizes of tensors must match except in dimension 1.
Expected size 2 but got size 1 for tensor number 1 in the list.
```

异常被 `except` 吞掉 → `_vad_intervals()` 静默返回 `[]` → **VAD 吸附失效但 LRC 照样能生成**，
所以这个 bug 极难察觉（诊断里只表现为 `vad_segments=0`）。

实测对照（同一段 179.3s 音频）：

| 场景 | VAD 段数 |
|---|---|
| 串行 4 次 | `[30, 30, 30, 30]` |
| 并发 4 线程（未加锁） | `[0, 30, 0, 30]` ← 复现竞态 |
| 并发 4 线程（加锁后） | `[30, 30, 30, 30]` |

因此模块内引入单个可重入锁 `_infer_lock`，把 **加载 + 推理**（fa-zh / VAD / CTC）全部串行化。
对齐单首只需 1~10s，串行的代价远小于静默降级。

## 六、后续可优化

1. **VAD 分段 + 段内对齐**（WhisperX 做法）：长音频上精度还能再提一档。
2. **人声分离后对齐**：复用已有的 PyMSS/BS-Roformer 把人声抽出来再对齐，可消除伴奏干扰（代价约 1.5 分钟）。
3. **纯音乐段判定**：目前间奏靠 VAD 静默切分，若能在前奏/间奏处插入空行提示，滚动歌词体验更好。
4. **前端可视化校验**：把字级时间戳画成波形对照条，让用户一眼看出哪行可疑并手动微调。
