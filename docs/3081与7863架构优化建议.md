# 3081 与 7863：关系诊断与整改记录

> 状态：**阶段一 + 阶段二 已于 2026-09-26 实施完毕并实测通过**。
> 7863 已置 `gateway_serve_ui = False`，即**纯 API**（根路径只返回引导页，不再直出 UI）。
> 阶段三（共享密钥 / 综合健康视图）为可选加固，未做。

---

## 一、整改前的形态（问题背景）

```
浏览器 ──► 3081 dsh（node，带 token）
             ├─ 侧栏：dsh 原生壳 + 六页签（lib/client.js）
             ├─ 主面板：<iframe src="/lab/?embed=1">  ← 反代到 7863 的 static/index.html
             └─ /lab-api/*  ← 手写反代到 7863 /api/*
                             7863 FastAPI（static/index.html 才是 UI 实体）
```

一句话概括：**UI 实体在 7863，3081 是个用 iframe 把它包起来的壳**。
由此衍生六个问题：双入口、反代一刀切 20s 超时、`/lab` 暴露 7863 整个根路径、
AI 链路从网关反向 spawn dsh CLI、进程治理分裂、端口硬编码散落。

## 二、已完成的改动

### A. 阶段二 · UI 归属 3081（根治）

| 改动 | 文件 |
|---|---|
| `/lab/*` 由 3081 从**本地磁盘** `static/` 读取，不再反代网关根路径 | `dsh-plugin/src/ui-panel.mjs` |
| 只有 `…/api/*` 走跨进程反代，网关其余路由不再对外可达 | 同上 |
| 7863 的 `/` 改为可开关：`gateway_serve_ui` 置 `False` 后退化为纯 API，只返回指向 3081 的引导页 | `settings.py` / `app.py` |
| 静态服务带 ETag 协商缓存 + 目录穿越防护（403） | `dsh-plugin/src/ui-panel.mjs` |

**实测（决定性）**：把网关端口指向一个不存在的 9999，`/lab/` 仍然 `200 / 161618B`，
`/lab/api/health` 才 `502`。也就是说——**网关挂了页面照常渲染，只有接口报错**。
旧实现下这必然是整页白屏，这是"iframe 套 7863 根路径"最大的故障放大器，现已消除。

> 关于 iframe：物理上仍保留（`<iframe src="/lab/?embed=1">`），但它现在指向的是
> **3081 自己的同源本地静态路由**，不再跨进程、不再经过反代。真正"拆掉 iframe"
> 需要把 161KB 单文件 React 应用组件化重写进 dsh 的 Slot，属于独立大工程，
> 收益（省掉主题/页签同步那几百行胶水）与风险不成比例，暂不做。

### B. 阶段一 · 反代换成正经实现

`dsh-plugin/src/ui-panel.mjs` 整体重写：

- **连接池**：`http.Agent({ keepAlive: true, maxSockets: 24, maxFreeSockets: 8 })`，
  旧实现每请求 `connection: close`，一次一握手。
- **超时分级**（旧实现统一 20s，大音频下载会被中途 `destroy()`）：
  | 类别 | 超时 |
  |---|---|
  | 探活 / 轻量列表 | 8s |
  | 媒体与大文件（wav/mp3/pt/gguf…） | 不限时 |
  | 生成 / 换声 / 转谱 / 音色训练 | 不限时 |
  | 其余 JSON | 30s |
- **半截响应不再污染**：响应头已发出后超时只收尾，不再塞 504。
- **客户端断开即销毁上游**，杜绝连接泄漏。

实测 74.4MB 伴奏 `wav` 完整传输 77,996,652 字节 / 411ms，无截断。

### C. 阶段一 · 端口集中化（消灭硬编码）

新增**唯一真源** `ports.json`（仓库根）：

```json
{ "gateway": 7863, "dsh": 3081, "audiocpp": 8080 }
```

- Python 侧：`src/ports.py`（`app.py`、 `settings.py`、`watchdog.py` 共用）
- Node 侧：`ui-panel.mjs` 读同一文件
- bat 侧：启动时用 PowerShell 解析同一文件
- 临时覆盖：`YUE2_GATEWAY_PORT` / `YUE2_DSH_PORT` / `YUE2_AUDIOCPP_PORT`
- 文件缺失或写坏 → 回退默认值，**配置问题绝不允许导致服务起不来**

### D. 阶段一 · 看门狗统一管两个进程

`watchdog.py` 重构为统一服务表，7863 与 3081 走同一套「探测 → 击杀 → 重启」逻辑。
顺带修掉两个**从上线起就失效**的缺陷：

1. **探活把 401 当离线**——dsh 根路径需 token，`urlopen` 直接抛 `HTTPError`，
   `probe()` 返回 `False` → `dsh_seen` 永远为 `False` → **3081 的守护分支一次都没触发过**。
   现在 5xx 以下一律视为存活。
2. **3081 只杀不拉**——旧逻辑击杀后要等用户手动重开。现在杀掉后重新拉起。
3. 新增：网关连续健康 2 轮而 3081 从未出现过时，**主动补拉一次**（只试一次，
   避免把"用户故意不开工作台"理解成故障而反复刷进程）。

启动参数抽出到 `scripts/启动dsh工作台.bat`，主启动脚本与看门狗共用同一份，
不会再出现改一处漏一处。

### E. 顺带修掉的两个真 bug

1. **MCP 工具自 `9dcb99b` 起一直是死的**：那次「业务模块归档 src/」把
   `mcp_server.py` 移进 `src/`，漏改了 git 跟踪的
   `dsh-plugin/_dsh_home/profiles/{web,headless}/cordis.patch.yml`，
   dsh 每轮对话都报 `can't open file '...\mcp_server.py'`——9 个 AI 工具全程不可用。
   已把两处路径改为 `src/mcp_server.py` 并验证可启动。
2. **插件仓库根推导错误**：dsh 会把插件**拷贝**到
   `_dsh_home\profiles\web\node_modules` 下再加载，靠 `import.meta.url`
   往上找永远找不到仓库根（实测推成 `...\node_modules`，静态页全 404）。
   现在改为 `YUE2_ROOT` 环境变量优先 → cwd 回溯 → 模块位置兜底，
   启动脚本显式注入 `YUE2_ROOT`。

## 三、改完后的形态

```
浏览器 ──► 3081 dsh（唯一入口，带 token）
             ├─ 侧栏：dsh 原生壳 + 六页签
             ├─ 主面板：<iframe src="/lab/?embed=1">
             │            └─ 3081 本地磁盘 static/index.html（不经网关）
             ├─ /lab/api/*    ┐
             ├─ /lab-api/*    ┴─► 7863 /api/*（连接池 + 分级超时；唯一跨进程通道）
             └─ /lab-status  → 探活（含 ui=local-static、ports、root，便于排障）

7863 FastAPI ── 纯 API：音乐生成 / 换声 / 音色 / LRC / 转谱
                  └─ gateway_serve_ui=False（当前值）→ `/` 只返回 3081 引导页
8080 audiocpp_server ── YuE2 GGUF 推理
```

> 双入口已消除：7863 的 `/` 实测返回 `200 / 1026B` 的引导页，不再是 161KB 的 UI 本体。
> 若要临时恢复直出（例如 3081 起不来时排障），把 `settings.py` 的 `gateway_serve_ui` 改回
> `True` 并重启网关即可，无需改任何路由。

## 五、残留与可选加固（阶段三，未做）

- **共享密钥**：3081 反代时带本地 header 密钥，7863 校验，消除 7863 裸奔
  （目前仅靠 `127.0.0.1` 隔离）。
- **`/lab-status` 扩展**：网关 + 引擎 + 队列 + 磁盘的综合健康视图。
- **AI 链路反向绕行**：7863 的 `/api/ai/chat` 仍会 spawn 一个 dsh CLI headless
  子进程（3081 本身就是 dsh）。要根治需把 AI 对话整体迁到 3081 侧、网关只管音乐，
  涉及 `runner.mjs` / `bridge.mjs` / `src/ai_*.py` 三条链路重写，工作量独立。
- **SSE 替代轮询**：`/api/events` 替换约 69 处前端轮询。
- **启动脚本的 PowerShell 依赖**：当前用 WMI `Win32_Process.Create` 无窗口启动
  （`Start-Process` 在本机代理变量大小写双份的环境下会崩），若日后迁移到纯
  `pythonw`/`nssm` 方案可彻底免掉这层 shell。
